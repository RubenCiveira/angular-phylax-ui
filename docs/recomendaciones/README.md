# Recomendaciones técnicas — phylax-ui

Auditoría del proyecto completo (1.830 ficheros versionados) para mejorar la **usabilidad**, la **adaptabilidad**, la **reducción de dependencias** y la **personalización de estilos**.

El proyecto es una **base generada a partir de plantillas** (cabecera `@autogenerated` en casi todos los ficheros). Por eso, casi todas las recomendaciones apuntan a **la plantilla del generador** y no al fichero generado: si solo se cambia el fichero, el cambio se pierde en la siguiente generación y no llega al resto de proyectos que usan la misma base.

## Cómo leer estos documentos

Cada fichero con sugerencias tiene cuatro apartados:

| Apartado | Contenido |
|---|---|
| **Estado actual** | Lo que hay hoy, con ejemplos de código reales. |
| **Qué cambiar** | La modificación concreta. |
| **Qué aporta** | El beneficio para el usuario final, para quien mantiene el proyecto o para el generador. |
| **Cómo enfocarlo** | Pasos, orden, riesgos y si el cambio va en la plantilla del generador o es local. |

Etiquetas que se usan:

- 🔴 **Crítico**: seguridad o error funcional visible.
- 🟠 **Alto**: impacto directo en usabilidad, en el tamaño del bundle o en la capacidad de personalización.
- 🟡 **Medio**: deuda técnica que frena la evolución.
- ⚪ **Bajo**: limpieza o mejora menor.
- 🧩 **Plantilla**: el cambio debe hacerse en el generador.
- 📄 **Local**: fichero propio de este proyecto (no generado o con valores específicos).

## Hallazgos principales

### 🔴 Para atender ya

1. **Hay un token de SonarQube commiteado** en [Makefile](../../Makefile) y en [sonar-project.properties](../../sonar-project.properties) (prefijo `sqa_`). Hay que revocarlo y sacarlo del repositorio (ver doc 01).
2. **Los valores de `editable-choose` no coinciden con el modelo.** Los formularios ofrecen `'CLIENT-SECRET-BASIC'`, pero el modelo, el valor por defecto y las claves i18n usan `'client-secret-basic'`. El valor por defecto no aparece seleccionado, las etiquetas no se traducen y se envía al API un valor en mayúsculas (ver doc 08).
3. **Las listas muestran secretos en columnas** (`secretOauth` y `registrationAccessToken` en oauth-client, `password` y `temporalPassword` en user, `password` en smtp-outbound-config y `apiKey` en resource-server) (ver doc 08).
4. **El menú solo registra 2 de las 26 entidades** (`tenant` y `users`). El resto de pantallas generadas no se puede alcanzar desde la aplicación (ver doc 04).
5. **`GlobalErrorHandler` no está registrado**: los errores no controlados no llegan a la telemetría (ver doc 05).
6. **El interceptor de step-up nunca se ejecuta**: `provideHttpClient()` se llama sin `withInterceptorsFromDi()`, así que `StepUpInterceptor` (registrado con `HTTP_INTERCEPTORS`) se ignora (ver docs 04 y 05).
7. **i18n incompleta o desubicada**: 17 de los 26 scopes solo tienen `es.json`. Los `en.json` se quedaron en 26 carpetas antiguas (`access/tenant`, `document/*`…), y el loader combina idiomas con `forkJoin`, así que un 404 puede tumbar el scope entero. Además conviven dos convenciones de clave (`access.oauth-client.*` y `access/oauth-client.*`), una de las cuales probablemente no resuelve (docs 08 y 09).

### 🟠 Mayor retorno

- **Reducir peso**: `public/assets/monaco` ocupa **21 MB** y `editorjs` 648 KB. Ninguna feature los usa (`editable-sourcecode` y `editable-markdown` tienen 0 usos), pero se copian a `dist` (38 MB). OpenTelemetry añade unos 9 paquetes al bundle inicial (doc 03).
- **Personalizar estilos**: no existe una capa de *design tokens* propia. Los colores están fijados en hex (`#f5f5f5`, `#333`, `#1976d2`…), hay tokens `--mdc-*` que Material ya no usa, estilos inline en las plantillas y una paleta fija `mat.$blue-palette` (doc 02).
- **Usabilidad**: textos sin traducir ("No content", "Refresh", "Footer", "Loading...", `alert('No route')`, `confirm(...)` en OIDC), páginas de error que pintan la clave i18n literal, tablas sin semántica ARIA y hasta 47 columnas por defecto en las listas (docs 04, 07 y 08).
- **Adaptabilidad del generador**: 344 `NgModule` + 344 componentes `standalone: false`, ningún `OnPush`, alias de importación mezclados (`app/...`, `@shared/...`) y código generado sin formatear (doc 08).

## Hoja de ruta propuesta

| Fase | Objetivo | Contenido |
|---|---|---|
| **0. Higiene (1 día)** | Seguridad y errores funcionales | Revocar el token de Sonar, corregir las opciones de `editable-choose`, quitar secretos de las listas, registrar `GlobalErrorHandler`, borrar `_no_Dockerfile`, `.scannerwork` y el servicio de rutas duplicado. |
| **1. Theming (3–5 días)** | Personalización total de estilos | Crear `src/styles/` con tokens propios (`--app-*`), tema Material parametrizable, quitar hex y `--mdc-*` del toolkit, sacar los estilos inline, autoalojar fuentes e iconos. |
| **2. Dieta de dependencias (2–4 días)** | Bundle y superficie menores | Monaco y Editor.js opcionales o bajo demanda, OpenTelemetry lazy, `crypto.randomUUID` en lugar de `uuid`, quitar `@angular/animations`, decidir sobre module federation. |
| **3. Generador v2 (1–2 semanas)** | Adaptabilidad | Plantillas standalone + `OnPush`, lista de columnas configurable, metadatos de campo (`sensitive`, `listable`), i18n coherente, menú y rutas generados desde metadatos, Prettier al terminar de generar. |
| **4. UX (continuo)** | Usabilidad | Estados vacío, carga y error traducidos; accesibilidad de tablas y menú; diálogos de Material en lugar de `alert` y `confirm`; selección de idioma y tenant en la UI. |
