## `src/app/bootstrap/menu.config.ts` · 🔴 Crítico · 🧩 Plantilla

**Estado actual**
```ts
export function menuRoutes(...): Routes {
  return [
    { path: 'tenant', data: { label: 'Tenants', path: 'Access' }, canActivate: [isAuthenticated], loadChildren: … TenantViewListRouteModule },
    { path: 'users',  data: { label: 'Tenants', path: 'Access' }, canActivate: [isAuthenticated], loadChildren: … UserViewListRouteModule },
    // { path: 'info', … }  ← código comentado
  ];
}
export function menu(): MenuItem[] {
  return [{ label: 'access', icon: 'badge', subItems: [
    { label: 'users', icon: 'group', route: 'users' },
    { label: 'tenants', icon: 'domain', route: 'tenant' } ] }];
}
```
- **Solo 2 de las 26 entidades** generadas tienen ruta y entrada en el menú. Las otras 24 (oauth-client, api-key-client, resource-server, role, templates, themes, snippets, notificaciones…) tienen su `*-view-list-route.module.ts` generado, pero **no se puede llegar a ellas**.
- Rutas y menú se definen **por separado y a mano**, con información repetida (`route: 'users'` ↔ `path: 'users'`).
- `data.label` es `'Tenants'` en las dos rutas (copia y pega) y no se usa.
- Las etiquetas (`'access'`, `'users'`, `'tenants'`) son literales y no se traducen.
- La ruta es `tenant` (singular) y la otra `users` (plural).

**Qué cambiar**
Un **registro único de features** que el generador escribe y del que salen rutas y menú:
```ts
// bootstrap/features.registry.ts  (@autogenerated)
export const FEATURES: FeatureEntry[] = [
  { group: 'identity', key: 'tenant', path: 'tenants', icon: 'domain',
    labelKey: 'menu.identity.tenant', permission: 'identity.tenant.list',
    load: () => import('@features/identity/tenant/routes/tenant.routes').then(m => m.ROUTES) },
  { group: 'access', key: 'oauth-client', path: 'oauth-clients', icon: 'key', … },
  …
];
// bootstrap/menu.config.ts   (escrito a mano, NO autogenerado)
export const MENU_OVERRIDES: MenuOverrides = {
  order: ['identity', 'access', 'template', 'notification'],
  hidden: ['user-federated-identity'],
  extra: [{ labelKey: 'menu.docs', href: 'https://…', icon: 'help' }],
};
```
- `menuRoutes()` hace `FEATURES.map(f => ({ path: f.path, canActivate: [isAuthenticated], loadChildren: f.load, data: { feature: f } }))`.
- `menu()` agrupa `FEATURES` por `group`, aplica `MENU_OVERRIDES` y usa `labelKey` con transloco.
- Separar **lo generado** (registro) de **lo personalizado** (overrides) en ficheros distintos.

**Qué aporta**
- Todas las pantallas generadas se pueden alcanzar.
- Regenerar no machaca las personalizaciones del menú (orden, ocultos, entradas extra).
- Menú traducido y con permisos.

**Cómo enfocarlo**
1. Que el generador emita `features.registry.ts` con todas las entidades que tienen vista de lista.
2. Crear `menu.config.ts` (manual) con los overrides vacíos.
3. Añadir claves `menu.*` al `public/i18n/{lang}.json` global.
4. Unificar la pluralización de los paths en el generador (`kebab-plural`).

## `src/app/bootstrap/layout/menu/menu.component.html` / `.ts` · 🟠 Alto · 🧩 Plantilla

**Estado actual**
- El `MenuItem` tiene `icon`, pero **la plantilla no lo pinta**. En modo `mini` (72 px) solo cabe texto cortado: el modo mini no sirve.
- Los ítems son `<a mat-list-item (click)="run(item, $event)">` **sin `href` ni `routerLink`**:
  - no se pueden enfocar con el tabulador (un `<a>` sin `href` no es focusable);
  - no se puede "abrir en pestaña nueva" ni copiar el enlace;
  - el lector de pantalla no lo anuncia como enlace.
- `run()` hace `alert('No route')` si el ítem no tiene ruta.
- El estado activo se calcula a mano: por **cada ítem** se suscribe a `router.events` (todas las navegaciones, de todos los tipos) y llama a `isUrlActive` recorriendo la configuración del router. Coste O(ítems × eventos).
- Los grupos son `<h3 matSubheader>` sin estructura de lista anidada. No hay `aria-current="page"`.
- Hay código muerto: `idioma()`, `tenant()`, `login()`, `logout()` y `title` no se usan en la plantilla.
- Copia el árbol del menú con `any` y lo muta (`copy.hidden = …`) dentro de callbacks, fuera de los signals.

**Qué cambiar**
```html
<mat-nav-list [attr.aria-label]="'menu.aria' | transloco">
  @for (group of menu(); track group.key) {
    @if (group.visible) {
      @if (mode() === 'full') { <h3 matSubheader>{{ group.labelKey | transloco }}</h3> }
      @for (item of group.items; track item.key) {
        @if (item.visible) {
          <a mat-list-item
             [routerLink]="[lang(), tenant(), item.route]"
             routerLinkActive #rla="routerLinkActive" [activated]="rla.isActive"
             [attr.aria-current]="rla.isActive ? 'page' : null"
             [matTooltip]="mode() === 'mini' ? (item.labelKey | transloco) : ''"
             (click)="select.emit(item)">
            <mat-icon matListItemIcon>{{ item.icon }}</mat-icon>
            @if (mode() === 'full') { <span matListItemTitle>{{ item.labelKey | transloco }}</span> }
          </a>
        }
      }
    }
  }
</mat-nav-list>
```
- La visibilidad por permisos se calcula **una vez** por cambio de usuario o tenant con un `computed` o `toSignal(combineLatest(...))`, no por evento del router.
- Quitar `alert`, los métodos muertos y la copia mutable.

**Qué aporta**
- Navegación accesible con teclado y lector de pantalla, enlaces reales y modo mini usable (icono + tooltip).
- Mucho menos trabajo por navegación.

**Cómo enfocarlo**
Reescribir la plantilla del componente. `RouteAccessService.checkRouteGuards` se sigue usando para la visibilidad, pero se llama una vez por ítem y por cambio de identidad.

## `src/app/bootstrap/layout/menu/route-accesible.service.ts` **y** `route-accessible.service.ts` · 🟡 Medio · 🧩 Plantilla

**Estado actual**
- Hay **dos ficheros idénticos**: uno con errata ("accesible") y otro correcto, cada uno con su `.spec.ts`. Los dos declaran `RouteAccessService` con `providedIn: 'root'`. `menu.component.ts` importa el correcto.
- `checkRouteGuards`:
  - devuelve el **primer** guard que sea `Observable` e ignora los siguientes;
  - pasa un `new ActivatedRouteSnapshot()` vacío, así que un guard que lea `route.data` o `params` recibe `undefined`;
  - no evalúa los guards de las rutas lazy (`loadChildren`), que aún no están en `router.config`.

**Qué cambiar**
- Borrar `route-accesible.service.ts` y su spec.
- Combinar **todos** los guards: `forkJoin(guards.map(g => toObservable(runGuard(g))))`, con resultado `every(r => r === true)`.
- En lugar de ejecutar guards de navegación para decidir la visibilidad, comprobar el **permiso declarado** en el registro (`feature.permission`) contra el ACL o los roles del usuario. Es más barato y no depende del snapshot.

**Qué aporta**
No hay dos servicios con el mismo nombre, la visibilidad del menú es correcta y no tiene efectos secundarios (un guard puede redirigir).

**Cómo enfocarlo**
Borrar el duplicado ya. La lógica de permisos va junto con el registro de features.

## `src/app/bootstrap/app.routes.ts` · 🟡 Medio · 🧩 Plantilla

**Estado actual**
- La función se llama `aditioanlRoutes` (errata).
- La ruta `''` → `HomeComponent`, que navega a `['en-EN', 'main']` en su constructor. Pero:
  - el idioma por defecto del estado es `'es'` (`AppStateService`);
  - `ContainerComponent` usa `'es'` como valor por defecto;
  - `AuthorizationAccessService.loadLastRoute()` usa `'en-EN'`;
  - `phylax-config.json` declara `available-langs: ["es","pt","fr","de"]` (sin `en` ni `en-EN`).

  Hay **cuatro idiomas por defecto distintos**.
- La ruta `'**'` aparece dos veces (raíz e hija), las dos con `UnknownComponent`.
- No hay `title` en las rutas (el título de la pestaña del navegador no cambia).

**Qué cambiar**
- `{ path: '', pathMatch: 'full', redirectTo: () => inject(DefaultsService).homeUrl() }`, con `redirectTo` funcional (Angular 18+), en lugar de un componente que navega en el constructor.
- Un único `DefaultsService` (o claves `i18n.default-lang` y `tenant.default` en la configuración) para idioma y tenant por defecto, usado por Home, Container y AuthorizationAccess.
- Añadir `title` con un `TitleStrategy` que traduzca: `title: 'menu.access.oauth-client'`.
- `provideRouter(routes, withComponentInputBinding(), withInMemoryScrolling({ scrollPositionRestoration: 'enabled' }), withViewTransitions())`.

**Qué aporta**
Arranque coherente con la configuración, títulos de pestaña útiles (historial, varias pestañas abiertas, accesibilidad) y transiciones suaves.

**Cómo enfocarlo**
Plantilla. `withComponentInputBinding` permite además recibir `:language`/`:tenant` como `input()` en `ContainerComponent`.

## `src/app/app.config.ts` · 🟡 Medio · 🧩 Plantilla

**Estado actual**
- `provideTransloco({ config: { availableLangs: ['en','es'], defaultLang: 'en', prodMode: false } })` y, a continuación, `provideI18nConfiguration()` **sustituye** `TRANSLOCO_CONFIG` con otro valor (de `phylax-config.json`). Hay dos configuraciones y gana la segunda, lo que despista. `prodMode: false` queda fijado también en la segunda, así que en producción saltan *warnings* por cada clave que falta.
- `provideRouter([])` + `ROUTES` multi desde `provideConfiguredRoutes()`: funciona, pero no es el patrón habitual.
- No registra `ErrorHandler` (ver doc 05: `GlobalErrorHandler` nunca se usa).
- `importProvidersFrom(OidcLoginModule)` (NgModule) en lugar de `provideOidcIdentity()`.
- 🔴 `provideHttpClient()` se llama **sin** `withInterceptorsFromDi()`. Los interceptores de clase registrados con `HTTP_INTERCEPTORS` (`StepUpInterceptor` en `OidcLoginModule` y el de `angular-oauth2-oidc`) **no se ejecutan nunca**: el flujo de step-up (`insufficient_user_authentication`) no se dispara (comprobado: no hay `withInterceptorsFromDi` ni `HttpClientModule` en `src/` ni en la librería). Ver doc 05.

**Qué cambiar**
```ts
export const appConfig: ApplicationConfig = {
  providers: [
    provideConfiguration(),
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter([], withComponentInputBinding(), withViewTransitions()),
    provideConfiguredRoutes(),
    provideHttpClient(withFetch(), withInterceptors([stepUpInterceptor])),
    provideAnimationsAsync(),
    provideAppTransloco(),            // una sola fuente: STATIC_CONF + isDevMode()
    provideAuthorizationAccess(),
    provideOidcIdentity(),
    provideInstrumentation(),
    { provide: ErrorHandler, useClass: GlobalErrorHandler },
    provideUiDefaults({ formFieldAppearance: 'outline' }),
  ],
};
```

**Qué aporta**
Una única configuración de i18n, `prodMode` correcto, errores globales registrados e interceptores funcionales sin depender de DI.

**Cómo enfocarlo**
Plantilla. Hacer el cambio de interceptor junto con la revisión de `step-up.interceptor.ts`.

## `src/app/app.component.ts` · 🟠 Alto · 🧩 Plantilla

**Estado actual**
- `get isMobile() { return matchMedia('(max-width:900px)').matches; }` es un getter que se evalúa en **cada ciclo de detección de cambios**, desde varias expresiones de la plantilla.
- El estado del nav (`navFull`, `navMini`, `navHide`) son tres booleanos con `@HostBinding`, no signals, y **no se guarda** (cada recarga vuelve a `full`).
- Hay propiedades muertas: `mobile = signal(false)`, `visibleMenu`, `menuStyle`, `headerCompact`, `headerHide`.
- `susbcription` (errata).
- Se suscribe a `appState.language` para `setActiveLang`, pero no actualiza `document.documentElement.lang`.
- El estado de arranque `bootstrap` depende de `identity.bootstrap('main')`. Si la identidad no responde (discovery caído), la app se queda para siempre en "Loading...".

**Qué cambiar**
```ts
readonly isMobile = toSignal(inject(BreakpointObserver).observe(LAYOUT_MOBILE_QUERY).pipe(map(r => r.matches)), { initialValue: false });
readonly navMode = signal<'full'|'mini'|'hide'>(readPref('nav-mode') ?? 'full');
readonly navOverlayOpen = signal(false);
host: { '[class.nav-full]': 'navMode()==="full"', … }
effect(() => writePref('nav-mode', this.navMode()));
effect(() => document.documentElement.lang = this.lang());
```
- Ponerle un *timeout* al bootstrap de identidad (`timeout(10_000)` + `catchError`) y mostrar un estado de error con "Reintentar".
- Quitar las propiedades muertas.

**Qué aporta**
Menos trabajo por ciclo, preferencia de menú persistente, `lang` correcto y la app no se queda bloqueada si el IdP falla.

**Cómo enfocarlo**
Plantilla del shell, con `ChangeDetectionStrategy.OnPush`.
